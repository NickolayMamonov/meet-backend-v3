# Timepad: локальный предпросмотр первого реального каталога

Этот инструмент **не импортирует события**. Он читает два локальных файла,
проверяет ручной отбор и выводит один JSON-отчёт кандидатов. Не запускает Spring,
не читает конфигурацию приложения или токены, не создаёт HTTP-клиент, не обращается
к БД, провайдеру, геокодеру или Mapbox. Ссылки проверяются синтаксически, без DNS
и переходов. Исходные файлы не изменяются; CLI не сохраняет отчёт самостоятельно.
Gradle при сборке записывает обычные build/cache-файлы.

## Запуск

Из корня backend, PowerShell, JDK 21:

```powershell
.\gradlew.bat --offline -q timepadPreview `
  "-PpreviewInput=C:\catalog\timepad.json" `
  "-PpreviewReviewed=C:\catalog\reviewed.json" `
  "-PpreviewAsOf=2026-10-17T00:00:00Z"
```

Пути передаются отдельными Gradle properties; пути с пробелами нужно заключать
в кавычки вместе с `-P...`. Unix: `./gradlew` с теми же properties.
Первый offline-запуск требует уже заполненного кеша зависимостей Gradle.
Команда не включает ingestion или scheduler; существующий Boot main не изменён.

Непосредственный JVM entry point:
`dev.whysoezzy.meet.ingestion.timepad.TimepadPreviewCliKt` с аргументами
`--input <file> --reviewed <file> --as-of <UTC-instant>`.
Все три аргумента обязательны, неизвестные и повторные флаги запрещены.
URL, UNC-пути, stdin, glob и загрузка источника не поддерживаются. Используйте
локальный диск, не сетевой mount или ссылку на него. `as-of` должен
заканчиваться на `Z`; текущее время не подставляется.

Дата выше — воспроизводимый пример, **не подтверждение актуальности событий**.
Предпросмотр исторического snapshot остаётся историческим.

## Два входных файла

Источник — ровно один JSON-документ в форме ответа Timepad:

```json
{"total": 1, "values": [{"id": 4242, "name": "...", "starts_at": "..."}]}
```

`values` обязателен и должен быть массивом. `total` необязателен, но при наличии
должен быть неотрицательным целым числом не меньше длины массива; неполный
snapshot допустим. Неизвестные поля источника допускаются. ID — уникальный
положительный signed Long, только JSON integer, не строка или дробное число.
Строковые DTO-поля не приводятся автоматически из чисел/boolean.
Дата/URL могут отсутствовать: это приводит к отклонению конкретной записи.

Второй файл — **ручное подтверждение конкретного snapshot**, не автоматически
сгенерированная классификация по названию или IT-тегам:

```json
{
  "schemaVersion": 1,
  "inputSha256": "<64 lowercase hex символа SHA-256 точных байтов источника>",
  "events": [
    {
      "id": 4242,
      "adultProfessional": true,
      "notTest": true,
      "format": "MOSCOW_PHYSICAL",
      "locationVerified": true
    }
  ]
}
```

Пример ID **не является разрешением на импорт**. Оператор лично проверяет,
что событие профессиональное IT для взрослых, не детское занятие и не тест,
и подтверждает очное московское место либо фактическое онлайн-участие.
`format`: только `MOSCOW_PHYSICAL` или `ONLINE`. Все три подтверждения —
обязательные boolean `true`; неизвестные/отсутствующие поля, пустой список,
дубли ID и ID вне snapshot запрещены. Любое изменение байтов snapshot, включая
пробелы, требует нового хеша и проверки. SHA-256 в PowerShell:

```powershell
(Get-FileHash -LiteralPath C:\catalog\timepad.json -Algorithm SHA256).Hash.ToLowerInvariant()
```

Оба файла — строгий UTF-8, без повторяющихся JSON-ключей, хвостового второго
документа или глубины вложенности свыше 64. Источник ограничен **5 MiB / 500
событиями**, review — **256 KiB / 500 записями**. Чтение ограничено cap+1 байтом,
а не только предварительной проверкой размера файла.

## Отбор и нормализация

- Сначала нужен ID в ручном отборе. Нерассмотренные записи — `NOT_REVIEWED`.
- Общий с провайдером маппер отклоняет пустую/неверную дату начала, неверную
  дату окончания и окончание раньше начала. Больше нет подстановки epoch zero.
  Поддерживаются offset `+0300`, ISO offset/UTC, local datetime и local date;
  для значений без offset используется `Europe/Moscow`. Некорректные календарные
  даты не округляются до существующих.
- Нужны непустое название и `asOf < startsAt <= asOf + 30 суток`.
- URL: абсолютный HTTPS, хост `timepad.ru` или его DNS-поддомен, без userinfo
  и с authority ровно `<host>` либо `<host>:443` (пустой, некорректный порт
  и варианты вроде `:0443` отклоняются), путь `/event/<тот же ID>` с необязательным `/`.
  Закодированные/неоднозначные пути не принимаются. Query/fragment сохраняются,
  но не участвуют в идентичности `(TIMEPAD, decimal ID)`.
- Очно: город после trim без учёта регистра — только `Москва`/`Moscow`;
  адрес непустой, не название города и не online-маркер.
  Человеком проверенный адрес **без координат допустим**, с предупреждением
  `COORDINATES_MISSING_MAP_UNAVAILABLE` и значениями 0/0, без геокодирования.
  Отсутствующий/пустой массив либо явная пара 0/0 означают отсутствие координат.
  Иначе нужны ровно два конечных числа: широта [-90,90], долгота [-180,180].
  Числа могут приходить строками согласно DTO Timepad. Диапазон не доказывает
  расположение в Москве — это часть ручного подтверждения.
- Онлайн: явное `Онлайн`/`Online` в городе или адресе (trim, без учёта регистра),
  согласованное с ручным форматом и общим маппером. `Москва` + адрес `Онлайн`
  теперь определяется как онлайн. Online-город + физический адрес неоднозначны.
  Отсутствующее место само по себе не доказывает онлайн. Ненулевые координаты
  конфликтуют с online, повреждённые отклоняются.
- Нужна хотя бы одна тема существующего `TopicClassifier`; его общая логика
  и IT fallback не изменены и не заменяют ручную проверку аудитории.

Первый отказ на событие имеет фиксированный приоритет:

1. `NOT_REVIEWED`.
2. `MISSING_START`, `MALFORMED_START`, `MALFORMED_END`, `END_BEFORE_START`.
3. `EMPTY_TITLE`, `NOT_FUTURE`, `OUTSIDE_30_DAY_WINDOW`.
4. `INVALID_SOURCE_URL`, `SOURCE_URL_ID_MISMATCH`.
5. `FORMAT_AMBIGUOUS`, `FORMAT_REVIEW_MISMATCH`.
6. `CITY_OUT_OF_SCOPE`, `ADDRESS_MISSING`, `ADDRESS_AMBIGUOUS`.
7. `COORDINATES_INVALID`, `ONLINE_COORDINATE_CONFLICT`.
8. `NO_MATCHING_TOPIC`.

## Отчёт и ошибки

Отчёт версии 1 содержит `mode: OFFLINE_CANDIDATES_ONLY`,
`databaseCompared: false`, SHA-256 обоих файлов, `asOf`, конец окна и зону.
`counts`: `input`, `reviewed`, `candidates`, `rejected`, `reviewedRejected`;
`input = candidates + rejected`, `reviewed = candidates + reviewedRejected`.
`results` отсортирован по числовому ID. У кандидата: `identity`, все поля
`normalized` (`RawEvent`), отсортированные `topics` и `warnings`. У отклонённого
события: ID и `code`; данные кандидата отсутствуют (nullable-поля JSON равны null).
Категории внутри нормализованных полей также отсортированы.

**Нет create/update/persisted-skip счётчиков**: без сравнения с БД нельзя
обещать конкретную операцию или отсутствие конфликтов уникальности.

Коды выхода JVM CLI:

- `0`: корректно завершённый preview, в том числе без кандидатов.
- `2`: ошибка аргументов/ввода, stdout пустой, stderr содержит один код.
- `1`: неожиданная внутренняя ошибка (`INTERNAL_ERROR`), без stack trace/payload.

Whole-run коды: `INVALID_ARGUMENTS`, `INPUT_IO`, `INPUT_TOO_LARGE`,
`INVALID_JSON`, `INVALID_SOURCE_SCHEMA`, `INVALID_REVIEW_SCHEMA`,
`TOO_MANY_EVENTS`, `DUPLICATE_SOURCE_ID`, `REVIEW_HASH_MISMATCH`,
`REVIEWED_ID_NOT_FOUND`. Никакого частичного успешного отчёта при ошибке ввода.
Ошибка вывода может прервать уже начатую запись stdout; такой отчёт непригоден.
При запуске через Gradle ненулевой JVM exit делает JavaExec/build неуспешным;
код самого Gradle не обязан совпадать с JVM exit.

## Проверки и границы готовности

```powershell
.\gradlew.bat --offline test -PskipPostgresTests --tests "*Timepad*Test"
```

Маппер, preview и CLI проверяются без Spring/БД/сети. Только тесты адаптера
`TimepadProviderTest` используют локальный loopback HTTP fixture, не Timepad.
Тесты CLI создают синтетические временные входные файлы и проверяют, что CLI
не изменяет их и не создаёт дополнительных файлов.

Этот этап не разрешает импорт, деплой, сохранение токена, новые обращения к
Timepad, scheduler, изменение demo-строк, геокодирование или mobile/Mapbox.
Отдельно требуются реальный проверенный manifest, лимит запросов, закреплённый
production artifact, backup/restore proof, ограничения create/update и rollback,
а затем явное разрешение на производственные изменения. Миграций здесь нет.
Откат локальной реализации не требует операций над данными.
